# Local signing export crypto

`TetherlessForge.min.js` is the unmodified distribution from **node-forge 1.4.0**, already pinned in `WebBootstrap/package-lock.json`. Upstream: https://github.com/digitalbazaar/forge. SHA-256: `d9b9074e6861200d676e25dcfe97889db5e8f4150bb766d29c491ad709a51b58`. The adjacent upstream LICENSE is retained. No runtime download or remote service is used.

`TetherlessSigningCrypto.js` is our local adapter. Both resources are hash-checked by `NativeEncryptedP12` before execution. JavaScriptCore gets Security.framework random bytes; `Math.random` throws. Secrets are passed as function arguments, never interpolated into source, logged or sent to a web view. A new context is discarded after each operation.

The pinned CodeSignKit `d0c67710fda9a2646b9e829cb2cf443892728371` `Sources/PKCS12Builder.swift` lines 15–19 accepts `password`, but lines 57–67 emit an unencrypted `keyBag` and lines 83–89 return a PFX without MAC. Therefore the native legacy `encryptedP12Data` is NOT an encrypted-export implementation. It is not used for external backups. Internal existing Keychain envelopes continue to rely on platform Keychain protection; no misleading claim of file encryption is made.

Native export requires successful resource checks, encrypted shrouded-key-bag+MAC construction, same-password platform `SecPKCS12Import` with exact cert/key binding, and empty/wrong-password rejection. Failure never falls back to the upstream builder. Native compilation, packaged resource presence and actual iOS import compatibility are independent gates; Node/OpenSSL interoperability is not iOS acceptance.

The exporter explicitly selects PBKDF2 **HMAC-SHA256**, retaining AES-256 and 100,000 iterations. On macOS 15.7.9, real memory-only Security imports rejected Forge's implicit SHA1 PRF at both 2,048 and 100,000 iterations (`errSecDecode`), while explicit SHA256 at 100,000 succeeded. OpenSSL AES/SHA256 and test-only 3DES controls also succeeded. Apple source corroborates the AES PRF assumption: https://github.com/apple-oss-distributions/Security/blob/3dab46a11f45f2ffdbd70e2127cc5a8ce4a1f222/OSX/sec/Security/p12import.c#L212-L225 . The pinned CodeSignKit parser likewise defaults an omitted PRF to SHA256, contrary to Forge's default SHA1. This correction does not weaken encryption or remove native readback.

New backup passwords are limited to printable ASCII, at least 12 characters, because the libraries' non-ASCII PBES2 password handling is not yet interoperable. No custom encoding or cryptography is introduced. Authenticated imports require MacData and retain bounded nested KDF work. A dedicated macOS synthetic consumer gate checks the actual pinned CodeSignKit parser/signature, Security container import and private-key possession, real web-export interoperability, and negative cases. Source preparation is not a claim that this new CI gate or physical-device acceptance has passed.

Native imports currently accept exactly one leaf certificate and one matching RSA private key (2048–4096 bits), not otherwise-valid CA-chain bundles. This fail-closed restriction prevents disagreement with the downstream parser’s first-certificate selection; both Tetherless exporters produce the supported single-leaf format.
