# One authoritative IPA input snapshot

Plan scope: INSTALL-01 and QA-02. This closes a specific input-consistency gap, not all signing, file-provider or resource-budget acceptance.

The reviewed prepared DownloadAppOperation validated/extracted an IPA from a source URL, then copied that original URL again to the install context's App.ipa. If the external document changed between those operations, the validated bundle and retained IPA could differ. The new native path first creates one bounded private snapshot and uses that same file for extraction and context.ipaURL. It never rereads the source to create the cached IPA after validation.

NativeIPAInput holds a security-scoped access claim when available and coordinates the external read with NSFileCoordinator. Only the source-to-snapshot copy occurs inside the accessor; signing and extraction run after the provider permission is released. Internal downloaded inputs use the same snapshot primitive without an external coordination request. Failed coordination never accepts the snapshot. The existing install context owns residual temporary data if coordination reports an error after an accessor already succeeded.

The production snapshot streams 64 KiB chunks, has a 1 GiB maximum matching the archive-input ceiling, rejects links/special files, never overwrites an existing destination, and detects source metadata/size changes during copying. The destination is created at mode 0600, excluded from backup on Darwin and protected after first unlock on iOS. Publication checks confirm the output path still names the descriptor written. Cancellation/failure removes only this invocation's partial output, not a substituted output. Fixed error categories do not include the external URL. The caller must own the private destination directory; this is not a defense against arbitrary code inside the app process.

Ten portable tests execute real files, descriptors and mutation/cancellation events. Four integration checks run the hash-locked transformation against exact native input blob 99e33a7b94fb26707d81d3dab7d25e68254c93ad and confirm the extraction/context paths refer to the same snapshot. Swift frontend parsing is not UIKit/Foundation native typechecking. Real iCloud/third-party providers, physical Data Protection, actual signing and install-wide disk/RAM admission require separate acceptance. ZIP parsing and signature correctness remain other boundaries; this helper does not claim to validate either.
