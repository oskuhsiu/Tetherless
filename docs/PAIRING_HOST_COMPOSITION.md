# Gated same-phone pairing composition

This source candidate connects caller-owned host pairing, staged container validation, protected-record promotion and onboarding presentation. Both `TETHERLESS_BOUNDED_PAIRING_HOST` and `TETHERLESS_STAGED_PAIRING_VALIDATION` remain undefined in product builds. It is not a shipped or device-accepted pairing feature.

The only existing app file changed is `Integration/Overrides/OnboardingView.swift`. The file-import cover keeps its existing selection, dismissal and diagnostic behavior. A separate generation owns the new pairing cover through physical dismissal. Initial setup and replacement use the same explicit Start action. Stored/imported pairing, normal renewal, startup and the existing protected store are otherwise unchanged. Preparation already copies `Sources/TetherlessCore` and `Integration/Native`; this packet does not change preparation transforms or enable capability flags.

## Ownership and promotion

`PairingSetupModel` requires a physical iPhone on iOS 27 or later and checks the actual `Minimuxer.shared.gateway` type. One task retains the model and the real `NativeMutationGate` process lease through native preparation, publication/listener shutdown, host handshake, validation, challenge cleanup and commit. The protocol host-role model is `Mac17,7`, matching the pinned native prepare contract; it is not evidence of the current phone's identity.

The existing host bridge reserves native entry before dispatch, copies the borrowed six-digit PIN during the native callback, generation-checks delivery, and joins native/cancel entries before freeing the handle and closing the original accepted descriptor. The new coordinator captures the accepted peer's numeric address before transferring that descriptor. No caller performs competing I/O or changes flags. The host and validator have separate one-shot tokens.

A user-initiated UIKit background task supports switching to Settings within the OS-granted window. The expiration callback immediately signals the thread-safe cancellation controller, then requests UI reconciliation. Cancellation clears and suppresses the PIN, including when the app becomes active again. There is no clipboard, notification or logging of the PIN. UI concealment while inactive is a best effort presentation measure, not a claim that OS screenshots or memory are erased.

A monotonic 120-second session budget covers listening and handshake. Discovery and validation share at most the remaining session budget or 10 seconds. Cancellation/deadlines request shutdown and still await owned completion; they never substitute for join. If the OS suspends the process before join, ownership remains retained until work can complete or the process exits. No background keepalive or recurring task is introduced. Background task availability does not guarantee enough time for same-phone pairing.

The thread-safe cancellation/commit decision handles expiration even while the UI actor is occupied. After joined validation and document cleanup, a synchronous winning commit calls the existing `PairingFileManager.savePairingFile` path and selects remote pairing. There is no await between the final winner and that save. `PairingPromotion` checks the protected target before and after commit under the lease. Failed/cancelled validation and failed challenge cleanup never call save. A possible post-rename failure reports recovery required and is not automatically retried. No temporary record is installed into an active gateway or cache to perform validation.

Saving follows the existing import storage contract. This packet does not reinitialize the live gateway, mutate a port override, or claim a successful renewal. The ordinary connection/renewal check and stored-record reuse still need acceptance evidence.

## Current-container validation and limits

Bonjour is an untrusted routing hint. The resolver admits at most eight services, eight addresses per service and four unique numeric endpoints. It accepts only the same canonical IP address as the host connection, including IPv4-mapped normalization and link-local IPv6 scope. It joins browser stop and every started service's stop acknowledgement before returning. A failure or timeout requests stop; no fabricated acknowledgement releases ownership. These are app-admission bounds, not bounds on all allocations internal to Apple's Bonjour implementation.

The candidate record is parsed and normalized once by `PairingPromotion`; exactly those bytes go to the staged validator and eventual save. `Bundle.main.bundleIdentifier` binds the container request to the running app. The native composite authenticates the staged record and obtains the existing House Arrest/AFC container channel without changing active state. The Swift bridge retains immutable buffers and its challenge borrow until synchronous native return, then retires all concurrent cancellation entries before freeing the token.

The challenge uses two independent 32-byte Security RNG draws: a 64-hex filename and a separate expected value. Only the relative filename is sent through the authenticated channel. The expected value remains local to native comparison. The app writes a fresh `0600`, backup-excluded, completely protected document at `Library/TetherlessPairingValidation/<random>.challenge`; protection is applied before its contents. The file and directory descriptors remain owned until validation is quiescent. Cleanup checks the still-open inode and never intentionally removes a replaced file.

A successful comparison shows that this authenticated channel could read the unpredictable document in this app's container. It does not independently identify hardware, prove user intent, or defend against an attacker who already has container read/write access or can relay an authenticated connection to that same container. Public/mutable UDID, the PIN and Bonjour metadata are not identity evidence. Another phone with only the random filename cannot satisfy the check without obtaining the separately random bytes. Container copying, compromise or such relay breaks that assumption.

The trusted Library directory and reserved child directory must have no competing writer; the process mutation lease serializes app-owned operations. `fstatat` plus `unlinkat` is not an atomic conditional unlink against an external container writer. This packet does not add persistent credentials, a new transport or custom cryptography. It does not claim secret memory is zeroized after release.

## Verification packet

The standalone command is:

`python3 Integration/verify_pairing_composition.py --source-root . --output-root evidence/pairing-composition-swift`

Create `evidence` first and use a new, non-aliased output directory. The wrapper snapshots hash-pinned inputs, runs Debug then Release with the selected Apple macOS Swift toolchain, and observes tool path/version afterward. It requires 41 unique fixture results and successful final XCTest suites; normal repeated aggregate summaries are accepted. It retains full bounded diagnostics, compiler identity, exact source hashes and cleanup sidecars. Four commands each have a 60-second deadline plus 5-second TERM and 5-second KILL/join allowances: at most 280 seconds, requiring a six-minute outer CI envelope. Missing or incomplete join evidence retains owned scratch and stops further commands. Only reports/logs/sidecars belong in the uploaded output directory.

The 41 fixtures comprise the previous 19 app-boundary cases, four cancellation-controller cases, three challenge-file cases, two numeric-endpoint cases, four combined validation/promotion cases, four Bonjour resolver cases and five validator Swift/C-spy cases. The fixture package supplies an explicitly synthetic `IDevice` C module. This exercises the exact Swift validator's buffer/token/borrow ownership with held C returns and cancellation, not the Rust implementation, generated header or actual ABI. Foundation browser/service operations are injected registration/delegate spies. The UIKit model/view and new Onboarding branch are excluded from this standalone macOS package and still require actual iOS compilation. The C spy cannot establish successful authenticated pairing or current-phone validation.

Local evidence: 18 wrapper tests and four source-contract checks pass; the C spy passes `cc -std=c11 -Wall -Wextra -Werror -fsyntax-only -pthread`.
