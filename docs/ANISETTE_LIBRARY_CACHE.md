# Managed Anisette library generations

This change verifies locally sealed cache integrity. It is **not** independent publisher authentication: the initial archive digest still comes from remote metadata. Binary provenance/rights remain a pre-handoff gate.

Each manager-owned local/remote library slot contains `.tetherless-cache-v1`. `current.json` is a bounded, versioned atomic record binding one UUID generation, the validated archive SHA-256, required library names and the complete extracted file/directory inventory. Every file has a size and SHA-256. Receipt parsing errors, unknown versions, unreadable files or mismatches are failures, not misses. Untracked legacy directories are not silently sealed or loaded.

Installation validates the archive before creating staging. SafeArchive extracts into a private generation, required files and all other entries are checked, files/directories are flushed, and the completed generation is moved into place. Only then is the current record atomically replaced and read back. Failures before publication keep the old pointer; interruption after publication selects the complete new generation on next read. Orphans are never selected by newest-time or directory scans.

The inventory reader uses no-follow descriptors, rejects symbolic/hard links and special files, checks metadata before/after streamed SHA-256, and bounds names/depth/count/bytes. It currently permits ASCII basename components accepted by PrivateFileStore, 4096 entries, depth 16, 128 MiB per file and 256 MiB per generation. A trusted sandbox parent and the native common mutation lease remain caller requirements; this is not protection against arbitrary code already executing in the app process.

Native local and remote ODA paths must resolve a valid generation before constructing an AnisetteClient. Clients are no longer reused from a presence-only cached reference. All reads during normal provider entry revalidate bytes. Informational isReady/libsDir access is not authority to load an unverified location. Local-directory mode now requires a managed receipt; loose user-supplied library folders are refused. A missing legacy receipt allows the normal remote download path to build a fresh generation without loading the old files. A corrupt receipt does not silently trigger a replacement.

Completed versions are protected by provider-owned shared usage pins. Reclamation takes exclusive ownership, verifies the active receipt, and removes only obsolete canonical generations and abandoned staging. Normal provider entry and install admission invoke reclamation. Busy providers defer cleanup; a four-generation admission bound still prevents unlimited growth until they release their pins. Unpinned repeated updates no longer exhaust that quota. The receipt and stable lock are never deleted. See CACHE_RECLAMATION.md for precise lifetime, cancellation and filesystem boundaries. Daily profile renewal reuses a valid current generation and does not reinstall libraries each day.

Tests execute actual CryptoKit SHA-256, real filesystem IO, and the production cache on Darwin. The extractor callback is explicitly synthetic; it does not pretend to execute a downloaded binary or a real CDN transaction. Native preparation separately wires the real bounded SafeArchive extractor. The Darwin suite is not compiled/executed by Linux swift test and needs the macOS/iOS CI result. Source syntax and transformation contracts are separate evidence levels.
