# Request-owned pairing document import

The first-setup picker is now an explicit UIDocumentPickerViewController, presented by a stable request in a root fullScreenCover rather than a Boolean fileImporter attached to the Form. The delegate belongs to the representable coordinator. UI/readiness updates do not construct or present a second picker. Teardown invalidates callbacks and disconnects the delegate.

PairingImportFlow admits one request at a time. Selection/cancellation is resolved once for the matching request. Its outcome is consumed only after that presentation closes. Repeated or stale selection, dismissal and completion events cannot act on a newer request. A dismissed presentation without selection is cancellation, not import. Valid selection keeps the request busy until the normal protected import completes or fails. Navigation remains disabled during presentation/import, while no native mutation lease is held during the user's browsing.

Open mode (asCopy:false) avoids an automatic raw pairing copy in Documents/Inbox. External reading holds the security scope, uses NSFileCoordinator with withoutChanges, and performs the existing no-follow bounded read inside the accessor. Only after coordination/read errors are checked does normal PairingRecord validation and protected storage proceed. The source file is neither edited nor deleted. Cancellation never invokes this read or changes pairing, account or renewal consent. A URL is transient UI state, not a persisted permission or support-log field.

Apple API reference reviewed: https://developer.apple.com/documentation/UIKit/UIDocumentPickerViewController and https://developer.apple.com/documentation/uikit/uidocumentpickerviewcontroller/init(foropeningcontenttypes:ascopy:). These document external security-scoped access, coordination and open/copy semantics; they do not establish the root cause of the observed blank Simulator sheet.

Nine core cases exercise production request transitions with synthetic URLs and no file/device mutation. Five integration contracts check concrete UIKit configuration, callback invalidation, native import ordering, coordination and unchanged strict UI assertions. The real UI route now requires TWO successive system-picker Cancel operations, verifies cancellation status and disabled Continue after each, then preserves the existing setup/resume/consent/recovery/cold-launch route. Its ten-second system-control wait is unchanged. A blank picker is still failure, not an app-owned Cancel substitute, warm-up bypass or fake pairing result.

The old fileImporter route repeatedly presented a blank container in the actual iPhone SE Simulator. This change removes the implicit Form-level presentation ownership and strengthens callback/import lifetimes. It is not proof of a particular Apple framework bug. Fresh native compilation and actual system-picker UI execution are required; core tests cannot certify picker presentation, selected cloud-file access, or real-device pairing.
