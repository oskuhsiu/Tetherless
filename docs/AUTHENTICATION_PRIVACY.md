# Authentication diagnostic privacy

This is a targeted correction to the pinned SideSign integration and native app logging sinks, not a complete security certification or live Apple authentication result.

`authentication_privacy.py` checks both reviewed input hashes before writing either file. It removes all 72 free-form log call sites in Authentication.swift, eliminates diagnostic copies of raw/decrypted payloads and preserves the actual SRP, request, token and verification code operations. Error/retry messages use fixed descriptions. A public-authenticate catch boundary reconstructs errors without raw NSError userInfo, arbitrary server descriptions, repair-URL query strings or underlying response dictionaries. Existing authentication decision categories, cancellation and numeric server codes are retained.

The SideSign logging boundary no longer evaluates inherited debugLog/verboseLog autoclosures, even when verbose mode is requested. Only typed AuthenticationDiagnosticEvent values can print. Payload/header formatting helpers discard all contents, including unknown keys and token suffixes. Enabling typed events never enables AnisetteKit verbose output. This intentionally reduces upstream diagnostics; migrate additional useful logs to typed events rather than restore raw interpolation.

The separate native app sink is now replaced by `native_logging_safety.py` using its exact pinned source hash. Its compatibility debugLog/verboseLog methods do not evaluate or print arbitrary autoclosures, and raw logging cannot be enabled. This closes the identified first-sign UDID/device-name, account/Team mismatch, certificate-subject and input-URL messages that previously reached the app logger despite the SideSign override. `formatLogMessage` returns a fixed omission marker instead of extracting potentially sensitive URL/description fields. Fixed `PairingImportDiagnostic` events and structured renewal summaries remain independent and unchanged. This is intentionally reduced diagnostic output, not a claim that arbitrary payloads can be safely regex-redacted.

The app-local `OperationLogging` protocol is a separate sink and is replaced in the same all-input-validated transform. Its instance debug/verbose methods also leave autoclosures unevaluated. Operation summaries now accept only exact SUCCESS/FAILED/CANCELLED outcomes and finite elapsed seconds in 0...86400; they ignore arbitrary operation/target strings and never read Error descriptions. This preserves bounded outcome/timing evidence without account, Team or app identifiers.

The reviewed error-history and source-refresh persistence routes now use a closed metadata snapshot through `error_privacy_safety.py`: fixed domain/category/outcome and fixed descriptions, with no raw userInfo, URLs, nested errors or server text. The original live error, source selection, cancellation handling and refresh result still reach their existing callers. Legacy history/source-error display and copy also reconstruct fixed metadata, but historical database bytes are not purged or migrated. [Exact persisted-error scope and limits](ERROR_HISTORY_PRIVACY.md).

The IDevice Rust logger initializer is now forced to its supported Disabled (0) console and file levels, with a nil file path, in the existing hash-locked `pairing_safety.py` gateway transform. This removes Debug's unconditional Trace selection, including when a caller requested false. Launch preferences, both settings toggles, renewal and Debug gateway start all converge on that one initializer; later requests still pass Off. The pinned Rust source installs its subscriber once, so a late false request cannot disable an earlier enabled subscriber. Keeping the existing initializer with no sinks reserves that global subscriber for a fresh process; this is not a runtime reconfiguration of an already-enabled process. The original PIN callbacks, wireless gates, pairing/renewal operations and `super.setLogging(enabled)` remain unchanged.

The gateway input is still exact original Git blob `e9310d0236e244813ce945236bdb99af2582f649`. Tests restore only the changed method and require every other byte to match the prior prepared gateway blob `1b0874f599b0f5ed4453476d2ddb46f71e58070c`, observed in the cb8e4dd native artifact. A native-call spy compiles the exact transformed method for Debug and Release and checks false/true/repeated requests always pass 0, 0, nil while preserving the Swift preference. Missing local Swift is an explicit skip; the parent native CI executes the test and compiles the actual gateway. These checks do not establish native binary runtime behavior or source/binary equivalence. [Pinned IDevice initializer](https://github.com/SideStore/idevice/blob/3e55c8486b2057e40c1f74aaaa1155c82341cf76/ffi/src/logging.rs).

EMProxy's separate native callback bridge and other libraries' direct output, historic database bytes and unreviewed persistence/export paths remain separate boundaries. The pairing safety transform removes its three identified PIN interpolations at source. These changes do not establish a complete dependency/binary logging audit or live-account privacy result. New native archive/Core Data/UI evidence remains pending for the persisted-error increment.

The interactive account-repair handler may receive a bounded HTTPS URL on the exact supported Apple hosts, with no embedded user credentials or unexpected port. Unsupported URLs use the existing official account fallback. A thrown repair error always contains the fixed account URL, not the server's query. No browser or external account is opened by the tests.

Tests compile and run the identical replacement logging code and authentication-error policy. The error test uses the actual upstream enum definitions with synthetic secret-bearing errors and checks reflected values, localized descriptions and bridged NSError userInfo. Logger tests exercise disabled/enabled modes and prove free-form autoclosures are not evaluated. Source-contract tests also require the original wire fields and server-proof check to remain. These tests do not execute the full SRP handshake, real 2FA or a live account. The native pipeline separately compiles the full patched SideSign and app.

Reference: https://developer.apple.com/documentation/os/generating-log-messages-from-your-code (prefer fixed, developer-defined diagnostic values).
